# 把项目经验变成可复用的 Agent 工作流

这个仓库提炼的是工程方法。迁移时先填写新工程的合同、配置和证据入口，再启用相关技能；源工程某个日期的授权、模型参数和性能目标不自动成为新工程的规则。

## 先确定当前有效合同

用一份短的任务合同回答：修改什么、保持什么、允许在哪些环境执行、验收使用什么指标、交付到哪里。记录基线 commit、目标分支、受保护配置、精度合同版本和有效启动参数。普通调用、诊断调用和基线调用应各有可查看的执行计划。

源工程的启动文档保留了多次目标变更：性能目标、prefix cache 默认值、FP32/BF16 计算合同和是否允许设备实验都曾变化。迁移后的规则应显式写明覆盖关系，不能从几个历史段落各挑一条拼成互相矛盾的合同。

| 源工程中的历史约束 | 可迁移规则 | 新工程必须重新确定 |
| --- | --- | --- |
| 旧 FP32 逐位门被授权的 BF16 合同替代 | 数学改变必须有独立、预声明且版本化的 oracle；旧合同保留作差异诊断 | dtype、舍入位置、累加类型、误差预算 |
| APC 默认开启、关闭、再开启出现在不同分支 | 保存实际生效的配置和完整 argv，按当前任务比较 | cache 默认值、预算、并行度 |
| 固定 candidate 一键入口 | 一份候选配置同时驱动生产入口与验证入口，验证实际路由 | 入口名称、候选开关、发布分支 |
| 不连接真机，由用户执行 | 每个任务明确设备访问与测试授权；未测项如实保留 | 谁可连接设备、执行范围、时间预算 |
| 特定短/长负载均需保住收益 | 性能验收覆盖任务指定的多个代表场景，不以平均值掩盖回归 | 长度、batch、输出预算、质量阈值 |
| 原项目固定设备、端口、模型路径 | 这些都是显式配置，非法值失败而非偷偷换环境 | 设备、SOC、端口、模型、缓存目录 |
| 原项目禁止读取特定失败实现 | 为项目定义参考来源边界；可保留失败证据而不继承不可信实现 | 允许参考的仓库、许可证、版本 |
| 每个文件强制引用巨大事故档案 | 使用症状索引与任务相关的直接证据，把复发风险落实到测试 | 事故分类、引用粒度、必读范围 |

依据：`AGENTS.md` 与 `oscar_ascend_agent_start.md`，`7047ce36`、`e70d7846`、`fdb8eba9`；环境选择见 `docs/python_environment.md@26cf6dc4`。完整来源范围见 [分支清单](../provenance/branches.md)。

## 一个主流程，专项知识按需展开

推荐闭环：确认合同 → 查现存实现与同类事故 → 建立最小可复现证据 → 提出一个可证伪假设 → 实现 → 分层验证 → 回填台账 → 交付实际启用的版本。

技能的入口只负责适用范围、输入、执行顺序、停止条件和输出证据。专项文档展开算子、图、部署、精度或 profiling；不要让每个专项文档另设互相竞争的目标。记录每个候选是提出、研究、待集成、已启用、退役还是证据不足，并保留重开条件。

实验卡至少写清楚：

1. 当前源版本及真实调用点；已观察到什么，什么仍是假设。
2. 一项改动及其不变量；新增内存、拷贝、同步和维护成本。
3. 预先冻结的精度、协议和性能判据，以及比较分母。
4. 要执行的最小验证矩阵、真实退出码和证据位置。
5. 结果、失败边界、是否纳入当前组合及下一步。

不要把旧实验卡中的项目数字直接迁移。例如历史单项倍率门后来被“相对最新基底的真实净收益”覆盖；保留失败记录不等于继续执行失效目标。

依据：`skills/oscar-quant-optimization/SKILL.md`、`references/experiment-template.md` 和 `docs/optimization_ledger.md@fdb8eba9`。

## 多 Agent 的任务书也必须有合同

给子任务指定文件所有权、输入证据、必读的相关事故条目、允许修改的接缝和必过验证。告知其他作者也在工作，避免回滚他人改动。分析与实现可以并行；对同一生产文件的变更、设备资源占用和最终集成应串行协调。

独立审查关注真实路由、证据和未覆盖边界，不能仅复述实施者结论。完成摘要需说明哪个证据影响了哪个设计决定；不要求子代理机械重读与任务无关的全部历史。

依据：`oscar_ascend_agent_start.md@7047ce36` 的档案驱动与子任务要求。本仓库将其缩减为按风险、按相关性读取，未搬运原始事故档案。

## 常见反模式

| 反模式 | 可执行的替代做法 |
| --- | --- |
| 先改代码，再调整精度阈值直到通过 | 在候选实现和测量前冻结合同；授权数学变化时另建版本 |
| 把历史热点当作当前热点 | 核对当前 source、dispatch、实际调用频度 |
| 同一个失败实验换名字反复跑 | 台账保留失败原因和明确重开条件 |
| 只有 probe 启用新算法 | 同源生成候选配置，检查正式入口的最终 argv 与算子选择 |
| 文档写“已支持”就视为验收 | 附证据层、版本、场景与真实状态 |
| 通过关闭 guard 或吞异常修复故障 | 保留最早错误与协议检查，修正原因；必要诊断显式开启 |
| 原样复制历史 AGENTS 和所有技能 | 导出通用方法、参数化模板及最小工具，重新填写项目约束 |
