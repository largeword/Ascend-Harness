# 部署入口与故障定位

先读取目标工程的配置优先级、安装方式、启动入口和允许操作的机器范围。使用当前环境与显式配置；不从旧日志继承卡号、端口、模型路径或远端访问授权。

## 五项关键判断

1. **一个入口对应一套有效配置。** 明确 CLI、项目配置、环境变量、默认值的优先级，保存解析后的关键设置与启动 argv。显式非法值应报错，不静默回退到其他设备。编译、probe 和正式服务共用候选配置，并验证最终进程加载的库与路由；生成了新文件不等于服务正在使用它。

2. **失败同时在终端和证据文件可见。** 安装、编译、探针和子服务实时转发 stdout/stderr，保存相位日志、状态与真实返回码。使用管道写日志时确保返回码来自被测命令，不能被日志工具成功掩盖。摘要控制篇幅，完整 traceback 落盘但不得只落盘而让用户手动寻找首次失败。

3. **按失败相位缩小问题。** 区分环境/ABI、构建、库加载、设备执行、图捕获/回放、服务就绪与请求完成。health 或 HTTP 成功不说明全部请求已完成；心跳仍在也不证明满足 deadline。先用现有日志和最小可复现路径定位，再运行有区分力的验证，不无条件重跑完整基准或改超时掩盖问题。

4. **探针是有范围的验收动作。** 完整部署入口中的必要探针失败后停止相关后续步骤。纯启动入口可在项目明确允许时跳过探针，但不能产出新的验收结论。NPU 探针在没有设备时应报告未执行或失败，不以 CPU 替代后宣称设备通过；CPU 排障作为单独证据保存。

5. **进程与诊断修改有所有者。** 用本次进程句柄、PID 文件或独立进程组限定清理范围，不全局杀同名 Python/服务。给探针设定期限和完整退出条件。若需错误归因，优先项目已有可关闭诊断接口；不要为定位破坏冻结 guard、增加常态同步回读或改变图路径而制造新的时序问题。

## 最小交付信息

输出首个因果失败、对应相位/日志、有效配置和源码身份、已修复范围及剩余验证。若任务只授权本地工作，交付可运行的目标机命令并标明设备结果未测；已有授权范围内的工作继续完成，不附加无来源的确认关卡。
