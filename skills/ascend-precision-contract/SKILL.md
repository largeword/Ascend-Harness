# 数值链与校准资产的补充核查

在当前精度分析或验收阶段读取已有 oracle、误差定义、校准资料及已接受计算语义。区分数学等价、指定舍入链一致与已授权近似算法，以当前有效合同为判定依据。

## 配合已有流程

已启用 CANNBot 时，精度类别与标准由 `ops-precision-standard` 路由；单算子调试沿用 `ascendc-precision-debug`，整网或 KV/attention 定界沿用 `model-infer-precision-debug`。使用本机实际加载版本的口径确认、模式检索、工具判定和回归流程；冲突以对应入口为准。本技能不自设默认容差、替换验证器，或跳过其源码阅读、API 检索与修复验证要求，也不新建角色、阶段或 gate。

以下仅补充复杂数值链与资产一致性的经验，回填现有报告。未使用该平台的独立工程仍可按已有 oracle 与项目合同核查；尚未确定标准时只报告误差事实，不自行宣布通过或失败。

## 按相关性选择的五项核查

1. **容差先于候选结果冻结。** 在试验前固定参考公式、dtype、归约顺序、误差度量、非有限值和状态字段规则。新授权的 BF16 或其他近似算法使用独立版本合同，旧合同保留诊断用途；不得观察失败后放宽阈值，或以旧逐位要求否决已授权的新舍入语义。

2. **参考实现不能复用待测错误。** 独立描述量化、旋转、中心化、clip、反量化、softmax、部分结果合并和逆变换的顺序与精度。中间结果提前舍入可能改变最终输出，即使每一局部误差很小。生产实现与 oracle 共享数学错误时，二者一致不构成正确性证据；测试 oracle 也不应成为隐藏的生产回退路径。

3. **校准资产属于计算合同。** 把模型版本、全局与局部头映射、TP 切分、配方、dtype 和 schema 绑定到校准文件。复用旧资产前验证原始统计和配方兼容性；文件存在不能证明可复用。CPU 离线拟合与在线推理回退分别标注，不混淆其执行位置或精度含义。

4. **局部代理不能替代完整输出。** 量化均方误差或 attention score 指标改善，仍可能因 softmax、value 相关性或跨历史累积而损害 attention 输出及模型质量。优先建立可复现反例，覆盖历史/current 混合、分页边界、尾块和不同数据尺度；再检查原任务要求的完整算子与质量指标。合成短探针只支持其覆盖范围。

5. **数值域与协议域分开验收。** 容差只用于合同允许的数值输出；metadata、错误码、guard、padding、有效计数和地址身份通常有各自精确约束。NaN/Inf、空块和越界输入按定义的错误域测试。修复误差时不能顺便改动状态协议、工作负载或数据集选择来改善分数。

## 回填已有报告

报告合同版本、独立参考、最小反例、误差分布及失效范围。分别给出局部数值、完整算子、图运行和模型质量状态；未做的质量测试不从局部误差推断为通过。
