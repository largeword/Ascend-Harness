# 图与缓存生命周期的补充核查

在当前流程已经进入图或跨请求状态适配、诊断或审查阶段时使用。读取目标运行时真实的调度、缓存分配和 metadata 契约，不以某个模型字段或固定长度阈值代替阶段语义。

## 配合已有流程

已启用 CANNBot 时，图适配沿用当前选中的 `model-infer-graph-mode` 或 Torch 编译入口；npugraph_ex 的 API、模式支持范围和文档获取规则交给 `torch-npugraph-ex-knowledge`，自定义算子注册交给 `torch-custom-ops-guide`，缓存实现交给 `model-infer-kvcache`。故障分流沿用 `torch-npugraph-ex-dfx-triage` 等当前入口。使用实际加载版本，冲突以该流程为准，不在此固化易变的后端、注册模板或硬件支持表。

本技能只把状态反例补入已有设计和回归，不改角色、阶段、审批或验收门，也不绕过平台对 prefill/decode、地址和注册语义的限制。独立工程可按自己的运行时协议使用这些核查点；存在多个平台入口时由现有主流程选路，本技能不另作仲裁。

## 按相关性选择的五项核查

1. **图地址稳定不等于输入不变。** 区分捕获期间固定的设备地址、每轮更新的内容、shape 上界及有效计数。用同一地址改输入后回放验证数据真正更新；捕获成功不证明回放正确，eager 成功也不证明捕获可用。探针应覆盖任务实际使用的 shape 和模式。

2. **用原生阶段标志决定读写。** prefill、decode、dummy、capture 和被明确丢弃的 draft 各有不同有效行语义。短 query 或 speculative width 也可能是真实 prefill，不能据此折叠成 decode。保留原生 mask、有效 token 数及已提交状态边界；不能从 slot 解析失败反推该行已被调度器丢弃。

3. **缓存身份包含代际。** 物理页号或请求 ID 会复用，缓存键需要能区分释放、重分配、分叉写与共享引用的身份。验证 prefix hit/miss、native free、请求周转后的状态；仅首轮命中不足以证明长期复用正确。若需保留引用，明确所有者、上限和最终释放点，不暗中改写原生 hash 或 lookup 语义。

4. **提交与读取的顺序必须可证。** 对 target/draft、MTP、SSM/卷积或窗口快照逐项说明：谁生产、何时提交、谁可读、何时失效。accepted 数量不能被用于访问尚未提交的列；一次 forward 的窗口或 cut 应保持约定的一致快照。异步搬运需要完成事件或等效的顺序保证，指针存在不代表数据可读。

5. **测试生命周期而非单个 tensor。** 最小序列包含分配、写入、命中、分叉/拒绝、释放、复用及捕获后回放。比较原生路径与候选的状态推进，区分允许的数值误差与必须精确的页引用、计数、错误域。主机模拟反例可以证明协议缺陷，但修复后的主机通过不能证明设备命中率或模型质量已恢复。

## 回填已有报告

画清或列出状态转换、所有权和捕获/回放边界，附能触发问题的最小事件序列及对应回归。分别标注主机协议、设备完成、捕获、回放和服务验证状态；保留可关闭候选的方式。
