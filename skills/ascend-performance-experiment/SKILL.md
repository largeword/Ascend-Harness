# 完整成本与收益归因的补充核查

在当前性能流程的分析或复核阶段使用已取得的证据。沿用本次允许的操作范围、保护场景和冻结参数，历史阶段的测速许可及目标倍率不自动继承。

## 配合已有流程

已启用 CANNBot 时，算子优化沿用 `ops-perf-optimize-workflow` 与 `ops-perf-acceptance-criteria`，模型优化沿用当前模型优化入口；采集由 `ops-profiling` 或 `model-infer-profiling` 负责，模型 profile 拆解由 `model-infer-perf-breakdown` 负责。读取实际加载版本；工具选择、采样协议、环境与波动门禁、Plan 状态和审批均按对应入口，冲突以 CANNBot 为准。

本技能不另定 warmup/重复次数/阈值，不自行改 profiler，不新设角色、阶段、gate 或平行台账。只将下面的归因检查回填既有 Plan。独立工程可用其已约定实验协议开展同样核查，必要时建立自己的实验记录，不依赖平台工具。

## 按相关性选择的五项核查

1. **一个候选对应一个可否证假设。** 记录当前基底提交/产物、真实调用点、热点证据、候选差分和预声明验收条件。旧热点可能已消失；本轮增量核对当前已接受组合，累计和最终收益引用最初冻结基线及平台既有结果工件。只做复核时复用有效工件，不据此自行发起测量。失败、暂缓和未完成结果保留根因与重开条件，避免换个名字重跑同一实验。

2. **比较完整路径并固定分母。** 两侧使用同输入、版本、配置和统计口径，包含新增 workspace、搬运、解包、同步、producer 及实际调用频次。完整测量已含的开销不能重复扣费。分开报告 `S = T_baseline / T_candidate`、时间下降 `1 - T_candidate / T_baseline` 和吞吐提升；对当前候选和对原生系统的倍率不能混用或直接相乘。

3. **容量、batch、吞吐分开建模。** decode 稳态可按 `实际 batch × 每请求每步有效输出 / step 时间` 检查，推测解码还受接受率影响。容纳更多请求不保证调度 batch 增长，更不保证吞吐同比增长；prefill、混跑、排空和服务端等待另计。压缩标签或 GM 访问量不能直接证明 HBM 带宽受限，需结合实际 Cube/Vector 与存储层级证据。

4. **时间只能按其时钟和依赖解释。** host 墙钟、设备时间、模拟器 ticks、父子阶段和多 rank 不能直接累加。串行且互斥的份额才可使用 Amdahl 模型；异步流水按依赖图关键路径计算。缺失调用数、未闭合 trace 或未知重叠时给出条件区间，不伪造完整占比。短 probe 和 microbenchmark 只支持局部结论。

5. **测量资源与完成证据明确。** 核对当前流程对同设备或同模拟器测量的隔离措施，避免并行任务互相污染。引用既定 warmup、重复、完成标志、期限和清理范围，不用本技能重新选择这些参数。保存原始样本及真实退出码；超时、磁盘满、孤儿进程或只启动未完成的轨迹均不是有效性能值。采样开销与关闭采样的性能对照分别记录。

## 回填已有 Plan 或实验卡

补齐假设、固定基底、保护场景、候选开关、完整成本、既有精度与协议判据、测量方法、原始证据、结论和下一项最有区分力的行动。沿用原流程的证据格式，并说明实际支持源码、CPU、构建、模拟器、设备、图、质量或端到端中的哪些结论，不把某一层成功扩展到其他层。
