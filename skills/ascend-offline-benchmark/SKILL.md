# 已有评测结果的离线分析

仅处理保存的日志、配置、逐样本结果及按需使用的本地 tokenizer。输入路径和字段覆盖来自参数；不启动推理或自动下载模型。统计前先确认一个 run、一个样本和一个失败的定义。

## 五项关键判断

1. **日志用来发现 run，逐样本数据用来计算。** 解析日志中实际输出目录，规范化路径并去重，保留空或中断 run 的跳过原因。兼容 JSON、JSONL 和明确的记录容器；聚合 results 文件不能还原长度分布，应寻找同 run 的 predictions。缺文件的样本数是未知，不是零；读保存的 Python 配置时只解析可支持的字面结构，不执行配置代码。

2. **token 长度必须量到 token 轴。** 优先保存的真实输入/输出 token 数。缺失时按照显式 tokenizer、保存的模型配置、目标项目配置等已说明优先级寻找本地模型；从完整消息和实际 chat template 重建输入，记录特殊 token、generation prompt 和模板差异。对字典取 `input_ids`，对单条 batch 取序列长度，不对字典键数或 batch 维度取长度。无法复现实际模板时标注重建口径，不能冒称实测长度。输出通常对原始回复独立编码、不加聊天模板，并注明是否包含 reasoning。

3. **复现评分规则并区分三类结果。** 使用该 run 保存的 postprocessor、reasoning 处理和选项提取策略。可评分的错误答案计入准确率分母；可评分但未能提取答案的回复同时计为未作答；请求错误、无效数据或缺必要字段按策略跳过并分类统计。tokenizer 导入/初始化失败是基础设施问题，不应只跳过首条样本后继续伪造结果。回复长度缺失只影响该长度统计，不能移除已有的准确率或未作答计数。

4. **平均值写明权重和覆盖。** 长度区间通常采用左闭右开。等权 run 均值是每个有样本的 run/bin 准确率再平均；pool 均值是合并正确数除以合并样本数，二者不能混称。空 run/bin 不按零分。未作答率分母是能够判断是否作答的记录；失败回复平均 token 数只使用长度已知的未作答回复，并显示已知数/失败总数。报告 run 覆盖、样本数、最小/最大长度，单一异常短 bin 要先检查长度轴而非盲目调小 bin。

5. **并行与抽样保留可复现性。** 有界线程池按 run 分工，worker 使用独立计数与 tokenizer 实例；涉及延迟导入和初始化时串行保护，其后可并行编码。输出按输入顺序稳定合并，不受线程完成顺序影响。抽取速度数据时固定 seed/区间/数量，保留完整实际 prompt，按所需 JSONL schema 输出，例如 `{"question": "...", "answer": "none"}`；另存选择条件与计数。占位 answer 的速度集不提供准确率证据。

## 最小交付信息

终端给出清晰的区间表、权重说明、覆盖和末尾错误统计，可按终端能力使用颜色。提供机器可读结果及字段口径；对缺失、跳过和重建值保留区别。最高观察准确率同时展示样本量，不把小样本最优 bin 写成确定的模型能力结论。
